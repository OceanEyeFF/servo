## purpose

## completion_signals

- 只含 `.aw/` 的旧目标仓库可以通过显式命令升级到 `.servo/`，runtime state 保持等价。
- 已存在 `.servo/` 的目标仓库默认阻断迁移，并给出可执行恢复建议，不静默覆盖。
- `.aw/` 默认不删除；迁移保留原目录或创建备份，除非用户显式确认清理。
- 覆盖安装后，Skills marker、payload fingerprint、legacy target cleanup 与当前 installer 规则一致。
- 升级烟测在 `/tmp` 临时目标仓库中覆盖 `.aw` only、`.servo` exists、两者同时存在、foreign marker、损坏 marker、dry-run、备份恢复场景。
- operator-facing docs 清楚说明旧 `.aw` 用户的升级路径。
- agents backend canonical skill target dirs 全部使用 `servo-*`；旧 `aw-*` 仅作为 `legacy_target_dirs` 被 update/reinstall 识别和替换。
- CLI diagnose/update 与 TUI guided diagnose/summary 会提示 legacy target dir convergence 的更新路径。
- 打包后的 `servo-installer` tarball 在真实旧目标目录中能完成 `.aw -> .servo` runtime migration、agents reinstall、`aw-* -> servo-*` target dir convergence、verify/diagnose 与幂等复验。
- `.agents` 与 `.claude` 同时存在时，packaged `--reinstall --backend bundle` 可以分别刷新两个 backend 并保持各自 target naming 与 managed marker 边界。

## acceptance_criteria

- 提供显式迁移入口，不把 `.aw -> .servo` 作为普通初始化时的隐式写操作。
- 迁移入口支持 dry-run，输出将执行的复制、备份、阻断或覆盖安装建议。
- 迁移入口支持幂等执行；重复运行不会破坏已迁移的 `.servo/` state。
- `.servo/` 冲突默认阻断；只有用户明确确认的恢复路径可以继续。
- 覆盖安装流程复用现有 `aw.marker` / legacy cleanup / payload fingerprint 机制，并通过测试验证。
- `/tmp` 目标仓库烟测覆盖主要迁移场景，不在源码树下生成测试 runtime state。
- 相关 installer 测试、folder/path/governance 检查通过。
- docs/runbook 与 usage entrypoint 同步更新。
- 没有 `product/harness/adapters/*/skills/**/payload.json` 继续声明 `target_dir: aw-*`。
- `/tmp/.tmpRepo` 能从旧 agents `aw-*` managed target dirs 通过 `update --backend agents --yes` 收敛为 21 个 `servo-*` target dirs，且 verify/diagnose 通过。
- 根 package `.tgz` 入口在 `/tmp/repo-rating-function` 旧目标目录中完成完整升级链路；不依赖 checkout-local Node script 直接运行。
- 模拟双 backend 目标目录中，bundle verify/diagnose 在迁移前后均对 agents 与 claude 报告 0 issue / 21 managed installs。
